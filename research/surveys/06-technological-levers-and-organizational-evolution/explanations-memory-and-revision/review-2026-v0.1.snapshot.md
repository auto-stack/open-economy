# 解释的记忆 接口与共同修订 2026年资料综述

版本0.1，资料整理截至2026年11月13日，服务第一部分第4单元“接口、记忆与技术杠杆”。本轮问题是：**一个解释经过有限检验后，怎样保存的不只是结论，还有让别人能够理解、质疑、核验并有条件复用它的依据？**

当前可支持的判断是：成果的保存、可访问、可重跑、解释的可信度和新场景适用性，应逐层检查。已有接口设计、来源模型、数据管理原则、计算研究实践及复算研究可提供具体机制；它们尚未构成适用于所有组织的统一知识积累定律。

本轮是问题导向的资料综合，采用L225–L228四项原始来源，复用L23并扩读L47。新主研究发表于2013、2016、2018年，2026是本综述整理年，不是全部来源的出版年，也不表示完成截至2026年的穷尽检索。各项类型、读段和未读部分见[原始阅读记录](reading-notes.md)，文件见[第47批归档](../../../../wiki/raw/round-47/README.md)。

## 从主体内修订进入可传递成果

[前一章](../../../../book/part-01/02-entropy-information-and-ordo.md)讨论异常、解释扩展、有限试验与修订。同一个主体在当时还能记住“为什么这样判断”，后来复用的人却未必知道当时看到了什么、排除了什么、付出了什么代价。压缩成一句结论，可能省去恰好决定能否复用的条件。

[Q4](../../../reviews/05-modules-interfaces-hierarchy.md)已区分设计责任、接口与层级；[Q5](../../../reviews/06-memory-prediction-reuse.md)已说明记录完好仍会过时、存储量不等于有效积累。本轮增加的是解释与证据的联系、版本变化、核验层次和多主体修订。一个解释可被很多人使用，仍不意味着它已获得很多份独立支持。

## 先分清保存和传递的对象

以下是本项目的**工作区分**，不靠命名证明现实机制存在。

| 对象 | 应与什么分开 |
|---|---|
| 解释或主张 | 表达它的文件；同一文件可能包含多个主张，同一主张也可能有不同表达 |
| 观测与试验记录 | 对记录的解释、推断和价值评价；原始记录也可能包含测量或录入错误 |
| 分析过程与运行 | 程序文字与某一次采用具体输入、版本、参数的执行 |
| 核验记录 | 被核验对象，以及核验方法、结果、检查范围与核验者 |
| 适用判断 | 原来在哪些条件下得到支持，与新任务是否满足这些条件 |
| 采用或发布决定 | 证据支持到什么程度，以及谁有权让共同项目依赖该版本 |

来源关系可以帮助找到这些对象，但不能把“由它产生”改写成“它证明了”，也不能把“某人审核过”改写成“审核覆盖了全部内容”。

## 接口是复用条件 不是结论的包装

Parnas的模块讨论提供一个有限的设计机制：尽量让外部使用者依赖明确约定，减少对内部易变决策的依赖。这里的信息隐藏不是要求知识保密。开放内部实现与保留抽象接口可以并存；公开所有细节也不能替代接口说明。

对一份可复用解释，本轮提出以下**接口工作方案**：说明它回答什么问题，输入和输出各指什么，单位、对象、环境和期限是什么，需要哪些依赖与前置条件，误差和失败以什么方式报告，以及何种变化要求重新核验。内部推导可以很复杂，但足以改变适用判断的条件不能被隐藏。

这只是对知识复用的设计迁移，不是Parnas1972已经证明的认识论定理。需要检验哪些条件应外显、记录负担多大、使用者能否理解，以及如何处理新场景中没有被预见的相互作用。接口兼容也可能只意味着格式没变，任务含义却已经改变。

## 核验应分层 而不是给一个总通过标记

| 核验层次 | 能回答什么 | 仍不能独自回答什么 |
|---|---|---|
| 可定位、可访问 | 能找到对象及取得许可范围内的材料吗？ | 材料是否完整、正确 |
| 记录完整性 | 当前内容是否与所指定版本相同？ | 当初记录是否真实、遗漏了什么 |
| 可重跑与数值一致 | 给定输入和环境，能否得到记录的输出？ | 方法是否适合问题、解释是否被支持 |
| 分析与证据审查 | 定义、程序、数据、假设、推断之间是否相符？ | 所有替代解释是否排除，是否能跨场景使用 |
| 新场景适用检查 | 新任务是否满足支持该解释的条件？ | 未观察的长期效果或全部社会后果 |
| 采用与责任判断 | 是否在当前风险、成本和权利条件下依赖它？ | 该决定天然正当或以后不需修订 |

Sandve等的建议具体支持记录版本、过程、中间结果及文字主张与结果的连接。FAIR原则则支持标识、元数据、许可、语义引用和来源等复用条件；它允许受限数据的访问管理，不等于无条件公开全部内容。

Hardwicke等对Cognition的研究提供了直接经验约束：公开文件与实际复算之间仍有距离。在选出的35篇文章中，11篇无需原作者协助即可复现目标结果，11篇需协助，13篇仍有部分不一致。这个样本有明确选择条件，复算也只覆盖部分结果；不能用它估计所有研究的失败率。研究还没有发现原结论明显被严重推翻的证据，部分案例信息仍不足。

本项目的[有限反例](models.md)进一步区分这些层次：旧程序把2、4、6的样本均值算成6；文件完好且重跑一致，仍不符合已声明的均值定义。修订后得到4，并保存旧版本。这个反例是条件演算，不是经验失败率。

## 反证 误差与边界怎样留在记录中

保存反面材料，不是把所有异议都直接认定为对主张的有效反证。需要记录异议针对哪个版本和哪项主张，来自什么观测或论证，条件是否相同，可能涉及测量、执行、分析还是解释，以及已经作过什么检查。

本轮提出一份**解释记录的最小工作结构**，供书章与未来知识库讨论，尚不作为AutoDown或AutoOS的实现规格：

| 记录内容 | 作用 |
|---|---|
| 主张、版本、作者／维护者、形成时间 | 避免把不同内容当同一对象，明确谁能回答问题 |
| 任务、变量含义、单位、对象、范围、期限与前提 | 使适用判断可以被提出和核查 |
| 数据、过程、参数、软件或工具版本及结果 | 连接文字解释与产生它的证据路径 |
| 正向证据、反向证据、异常与替代解释 | 使读者看见支持程度及未解决的分歧 |
| 误差定义、样本／测量不确定性、模型残差与未评估项 | 避免把不同不确定性压成一个“置信度” |
| 检验方法、检查者、覆盖范围与结果 | 区分检查完成、问题未解与尚未检查 |
| 修订提议、理由、所见资料、审查与采用决定 | 保留改变的时间顺序与责任；更正不抹掉旧错误 |
| 后续使用与依赖、复核触发条件、维护安排 | 尽可能让重要变化传到使用者，而非只停在源文件 |

缺失项应明确标为未知或未评估。一次最大残差不等于未来误差上界；数值误差、统计不确定性和模型失配也不采用同一符号混算。把“异常”升级为“反证”，还需检查它是否真与该主张在所声明条件下的预期矛盾。

W3C的来源模型能表达实体、活动、责任、派生及修订，还能追踪一份来源描述本身由谁提供。它不直接定义上述全部证据关系。特别是其Invalidation指实体的终止或过期，不等于解释被证伪；本书不混用二者。

## 共同修订怎样容纳分歧

Nosek等的论述有助于保存一个关键区别：结果出现以前的预测和分析计划，与看到结果后形成的解释。原文允许透明记录实施变化，讨论保留检验集和同时存在的不同预测，也承认预先登记不能消除有偏分析和选择性叙述。探索和修改不应被假装成事先已经成功预测。

据此，本项目提出一条**共同修订的工作程序**：

1. 质疑、错误报告或新证据首先关联到明确版本与主张，保留原始记录。
2. 区分可重跑失败、计算错误、条件不符和解释竞争；仍不清楚时保留未决状态。
3. 提出修订并说明修改对象、理由、已见资料与拟作检验；探索结果与独立检验分开。
4. 审查修订对既有证据、接口和后续使用的影响，允许不同解释并存或形成分支。
5. 对被共同采用的版本，记录决定者、依据、异议、适用范围及生效安排。
6. 沿已知依赖通知或标记受影响的使用，要求按风险复查，而不是把所有下游结果自动判错。

提交质疑、提出方案、审核证据、发布共同版本和决定实际采用，是不同权限。来源记录谁参与了活动，并不独自决定谁应享有哪项权限；开放参与也不能省去授权与受影响者保护。如何选择治理程序，是需要另外比较的制度与价值问题。

依赖追踪还不完整：隐含假设、口头传播和未登记使用可能漏掉。维护者离开、资源不足或纠错不获回报，也可能使程序停转。FAIR补记中一个持续文档地址的迁移，展示了维护可涉及定位变化；不能把这种更新误认成理论内容被否定。

## 何时成为技术杠杆

此前有限复用模型已比较保存、检查、更新与重新制作。本轮补充一个比较口径：复用的收益，应与查找、理解、权限处理、核验、适配、协调和后续维护共同核算，再与从头完成同一任务的可行替代相比。已经支出的历史成本、当前新增成本、长期公共维护与单个使用者所得收益需分别记账，不能重复扣除或跨单位相加。

接口和共同记忆成为杠杆的条件性机制在于：让有用成果能够跨任务被找到、理解、组合和重新检查，同时避免把错误的传播误算成知识增长。这里的收益可能表现为少做重复工作、更快发现失配或更容易定位修改，不能直接换算成一个无量纲Ordo倍数。

共享同一来源的很多副本、很多引用或很多AI回答，并不等于很多次独立检验。若所有使用者继承同一错误，传播效率更高也可能扩大损失。这个风险有既有Q5模型支持的条件例子，本轮不宣称已测量其在整个社会中的规模。

## 论证地位及下一步

| 内容 | 当前地位 |
|---|---|
| 接口分配责任、来源／修订表示、FAIR条件、计算记录建议 | 文献设计机制、规范或方法，不统称实证定律 |
| Cognition的数据复用与目标结果复算 | 有限定样本、设计及检查范围的经验研究 |
| 重跑一致仍可能计算错误；依赖图标记复查 | 给定有限例子的条件推论 |
| 解释记录结构及共同修订程序 | 本项目工作方案，尚未验证最优性或实际运行效果 |
| 记录边界与反向证据能否改善复用净收益 | 待验证假说，必须计入记录和核验负担 |
| 审查、采用、退出和风险分担的权限 | 制度与价值主张，不能从信息物理关系唯一推出 |

下一轮优先比较：同一材料仅存结论、附完整文件、以及附主张—证据—边界关系三种做法，使用者能否以可承担的时间识别错误与不适用；怎样防止记录过多反而遮蔽关键条件；修订通知在不完整依赖网络中能覆盖谁；核验与维护怎样得到持续投入。先做内部对照，不冒充真实使用者或外部运行数据。

书稿可据此从“有限检验”进入“可核验的共同记忆”，再由保存、组合与修订进入演进。主体内修订、知识在群体中的传播、制度变迁和跨代演化仍分别解释。详见[章级接口](chapter-evidence.md)。
