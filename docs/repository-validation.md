# 书稿与来源包的版本检查

本仓库有两种正常阅读环境：只检出Git书稿与来源描述，或另外安装本地来源资料包。两者均使用`research/tools/repository-package.py`检查，不重跑会改写历史审计的旧工具。

## 只取得Git书稿

运行`python research/tools/repository-package.py check --mode tree --revision HEAD --output .local-artifacts/package-check.json`。检查实际Git对象中的框架、模型账目、链接和纳管范围；没有安装的原文报告为可选资料未安装，不称损坏，也不声称原文SHA已通过。

历史字节快照中的链接按它原来的位置解释，可阅读的0.3历史副本另行调整了链接。公式代码和代码块不被误当Markdown链接。检查发现真正缺失的必需文件、未知来源路径、误纳入的完整载荷或哈希不符时返回失败。

## 持有完整本地来源

相同命令还会核对清单中实际存在的档案文件；本地ZIP存在时检查其SHA256。资料包生成时另已核验ZIP目录、CRC和1358个解压后文件哈希，原件仍在原位置。资料包清单见[来源包](../wiki/archive/README.md)。原件核验和资料公开再分发范围是不同判断。

## 提交与标签

提交前使用`--mode index`检查实际暂存对象；标签只在提交后的精简克隆复验通过后创建。瞬时执行回执保存于忽略的`.local-artifacts/versioning`，避免把包含自身的新回执递归写进待检查版本。稳定的规则、来源包清单和阶段说明由Git保存，具体提交与标签对象通过Git查询。

检查覆盖六部分 28 单元，根据所选版本的目录逐份核对章稿及对应论证卡。框架标签有 11 对，第三部分本轮初稿收束时有 16 对。另核对纲领 0.4、79 条总表的基线字节、19 笔假设现金交易守恒以及本地链接。

后续来源批次的文件依据各批次清单单独核查。原始来源包仍按其历史校验值验证，包内收录过的 Git 文档（例如持续更新的来源目录）与旧版有差异时单独列出。归档所保留的逐字副本按批次中记录的原位置解析链接。检查结果只涉及资料完整性和上述框架项目。
