# 全书框架基线的完成标准

2026年11月12日。以第39轮研究后的六部分、28个候选单元为评估对象。主要议题已经基本齐备，可以停止按新话题不断扩张目录；还需要一次有边界的框架收束，才能将这一版标为可持续写作的基线。统一Ordo理论的成立、完整系统综述和AutoOS实证效果不属于同一个里程碑。

执行更新：第41轮完成三项框架内容并验收第1–4项；第42轮按用户要求落实第5项Git纳管、独立来源包及完整／精简环境检查，见[实施记录](../research/reviews/42-git-baseline-and-source-package.md)。`framework-v0.1`作为Git标签记录实际修订，不在正文复制会形成自引用的提交哈希。以下保留本页制定时的范围与标准，旧阶段审计不回写。

## 当前已经确定的内容

全书保留通用组织基础、人、共同生活、多种人群组织、经济机制和Open Business六部分。人的维持、目标、承诺、意义已经形成连续章稿；合作与竞争共同进入组织和经济分析；财富、货币、价格、信用与再投入已有专题依据；开放成果的回流与维护已经进入替代制度比较。

现有11章讨论稿与11张论证卡，其余17单元已有问题与向后交付的位置。11/28只描述章稿数量，不是理论成立比例或框架完成百分比。正式79条总表未变化，只有物理实现这一继承性基础承诺，尚无已确立的普遍群体行为新公设或统一Ordo标量。

第32轮复核提出的术语、组织形成、经济连接和制度比较，已分别在第33–39轮获得补充。经济和应用部分的跳跃明显缩小；第一部分的理论承诺、第四部分的跨组织外推，以及AI背景下的收入与分配闭环，仍需合起来核对。

## 最后一轮框架收束限定三项任务

| 任务 | 本次基线必须交付 | 不作为本次完成条件 |
|---|---|---|
| 理论核心与全书承诺 | 一份最小理论说明：哪些已有结果可以直接使用，哪些需要领域假设，Ordo与影响力哪些尚待度量，怎样支持或反驳主要解释；说明书中何处依赖它们 | 先证明所有组织都服从一个统一标量，再允许起草全书 |
| 不同组织的共性与差异 | 用家庭照护、雇佣企业、开放共同体、公共服务四种对照，检查参与、依赖、退出、权力、维护和外部后果；至少明确一条相同机制在何处停止外推 | 完成家庭到国家的全部社会史，或把概念对照宣称为新的跨组织实证 |
| AI时代的经济闭环 | 把知识服务与实体设备服务放进同一因果图：技术与投入→所有权与控制→收入与购买力→实际支出→经营回款→维护及再投入；标出税收、公共预算、保障、能源材料和外部代价的接口 | 完成一般均衡、金融危机、国际经济与全部AI技术的系统综述 |

这三项优先使用已有材料检查结构。只有某项关键连接缺依据、且不能通过缩小主张解决，才开启定点补读；不再为了增加主题覆盖率启动新一轮大规模搜集。

## 哪些问题需要明确归位

公共权力与自愿契约不能混写。第四部分关于国家和公共服务的单元，应承担授权、不能自由退出者、公共责任及纠错的接口；第五部分说明税收、公共支出、保险与保障怎样影响收入和下一轮投入。可以限定篇幅，不宜只在应用结尾附带提到。

物质边界不能由数字复制替代。第一部分的输入与维护、第五部分的生产积累及第六部分的技术条件，应显式记录能源、材料、设备寿命和外部代价。气候政策、国际贸易或金融危机的完整理论可以列为外部范围；若正文使用相关结论，仍需相应依据。

善恶、意义、公平和人的基本机会已有位置，继续以独立价值理由承担评价。贡献归因、支持行动的激励和正当回报分别处理，不能让“更高Ordo”或某个分数代替这些论证。

## 框架基线的验收

1. 六部分、28候选单元的核心问题与向后交付可逐项对应；有必要新增或合并的单元一次说明理由。
2. 上述三项各有一份紧凑说明，并能接到具体章节。不存在仍以“后面自然会推出”占位的关键连接。
3. 每个核心结论能辨认定义、假设、推导、经验依据和价值前提；未解决的核心假说有明确位置及失败条件。
4. 已知重大范围选择写清楚，普通证据待补与会改变整书结构的缺口分开。
5. Git纳管范围、来源档案的独立保存方式与标签说明已经落实，能区分书稿、来源和派生资料。

满足这些条件即可建立`framework-v0.1`。这个标签表示问题框架、主要承接和研究边界已有可审查版本；不表示统一理论已证明、28单元全写完或Open Business效果已经验证。理论研究若改变结构，后续版本如实修订。

按现有材料，我判断还需要一轮集中框架收束，再加一次版本与归档整理；这是工作量判断，不是已测得的工期。若收束发现核心论证必须依赖尚不存在的新定理，应如实标出，并决定将其作为待检验主张还是缩小全书承诺，不能仅为打标签略过。

## Git与标签的先后

现在就适合让原创书稿、研究记录、模型、书目及校验信息进入版本管理，保存可追溯的进展；框架标签等上述收束完成后再建立。无需等全部survey和正文完成才纳管，也不应把原始下载资料全部推入公开仓库。

具体分类见[版本管理与来源归档方案](versioning-and-archive-policy.md)。第40轮当时只做盘点与方案，后续纳管与标签按第42轮实际操作记录；没有远端推送。
