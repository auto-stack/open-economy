# 三种保存方式对错误定位 适用判断与复用成本的影响

2026年11月13日。使用同一组内部结构化材料，比较仅保存结论A、附完整材料B、增加主张—证据—适用边界索引C。**在给定检查规则下，完整材料和正确索引都能完成七题；索引主要将整理工作前置，并减少后续检索。** 它没有增加实质证据，也没有提高原材料本身的可靠性。

这是脚本化内部对照，材料来自本项目旧例子的合成变体；没有真实使用者、人工计时或独立盲测。使用者的语义判断由明确规则代替，不能据此估计人的理解速度或现实错误率。[执行前协议](protocol.md)、[程序](compare.py)、[完整结果](results.json)、[题目](fixtures/questions.json)和[参考判断](fixtures/reference-decisions.json)公开可查。参考判断没有加入使用材料，也不参与索引生成和判定器选答案。

## 比较什么

七题涵盖：错误分母、文字与所指运行不一致、样本均值用于总体预测、曲线超出范围、范围内反向记录、正确均值对照、其他环境的异常。均值数据为2、4、6；曲线使用x²及已检查的有限点。异常由本项目人为给定，不是新增实测。

A保留结论中已写出的范围，不刻意删除限定条件。B/C的全部辅助记录字节相同。B每题完整扫描；C按预先生成的归属索引读取。二者使用同一套核验规则。B还允许自行建立一次相同索引，作为必须报告的补充比较。模型不把B的逐题扫描当作最优阅读方式。

B的结构化记录已经含有明确归属字段；C机械整理这些相同关系，比较的是预先保存可查询索引的效果。从自然文本中识别、判断并建立主张—证据—边界关系的工作没有被测量，不能把扫描50条记录说成完成了全部知识组织劳动。

## 主比较的结果

下表采用30条相关辅助记录、20条无关记录，共50条辅助记录的情境；每种方式另有同样的七条结论读取。

| 指标 | A 仅结论 | B 完整材料逐题扫描 | C 完整材料加关联索引 |
|---|---:|---:|---:|
| 完成参考判断 | 2／7 | 7／7 | 7／7 |
| 定位三项指定问题 | 0／3 | 3／3 | 3／3 |
| 证据不足或预算停止 | 5 | 0 | 0 |
| 该组材料中错误接受 | 0 | 0 | 0 |
| 逐题读取辅助记录 | 0 | 250 | 22 |
| 逐题辅助记录字节 | 0 | 27,355 | 2,402 |
| 查索引次数 | 0 | 0 | 5 |

A完成的是两项“请求超出结论明示范围”的判断。它没有完成其他五项核验，但也没有错误地接受它们。因此2／7是本轮完成情况，不能改写成结论保存方式只有某个“准确率”，也不能说其余五项结论都错。

B与C都发现错误分母、文字—运行不一致和环境内的反向记录。其他环境的异常被保留，在本次指定环境中不直接当作反例。曲线可用判断仅涉及有记录的检验点，不证明整个连续区间有效。

## 建立与维护成本不能省略

C另需检查50条辅助记录、写入50个索引条目；本批索引4,405字节，首次载入它并验证5,471字节的资料快照，均不包含在上表逐题字节数中。索引建立的扫描另读5,471字节。在这组七题中，C的逐题读取加首次索引载入和快照验证为12,278字节；再加建立扫描为17,749字节。它们仍不包含人的理解、审查、记录编写、权限处理及维护时间，不能作为完整经济成本。

| 保存空间 | 字节 |
|---|---:|
| A结论文件 | 2,080 |
| B结论及完整内部材料 | 7,551 |
| C结论、相同材料及索引 | 11,956 |

**完整资料可以自己变成关联资料。** B自行建立同一索引以后，逐题判断、读取次数和索引内容都与C相同；若同样保存和分享索引，也承担相同的建立及初始化成本。优势来自索引能否被正确建立、保存与多次利用，不是某个文件夹天然更有知识。

对一项正确均值请求，逐题扫描B读取1条结论和50条辅助记录；索引方案读取1条结论、4条辅助记录并查1次索引。仅在“读一条记录与查一次索引各计1单位”的假设下，再把每条索引写入成本设为0、1、5单位，相对重复冷扫描首次严格节省的使用次数分别为2、3、7次。这只是操作权重的敏感性结果，未纳入上述字节校验及人的整理成本，不能称为真实投资回收期。B自建索引得到相同结果；版本更新若全量重建，要再次支付建立成本。

## 有限预算与材料膨胀

在每题最多读取4条辅助记录时，A与逐题扫描B完成2题，C完成5题；上限为5条时C完成7题，而B要达到50条上限才能在该策略下完成7题。结论读取和索引查询另记，C的50条前置整理没有消失。这是把可复用整理结果交给后续使用者的条件性效果，不是无成本取得了新信息。

无关材料为0、20、100条时，逐题扫描B分别读取150、250、650条辅助记录，C均读取22条。C的建立检查却分别增至30、50、130条，索引空间也随之增加。更好的全文搜索、缓存或别的阅读策略可能改变比较，本轮没有测试它们。

## 关联本身也需要核验

人为把一条环境内的反向记录从C05错归给C06，原始文件和文件摘要仍保持不变，全部记录ID也仍恰好出现在索引一次。C05的读取器却漏掉冲突并返回可用判断；读取C06时才发现归属不符。这不是对错误发生概率的估计，而是一个关系错误的反例。

完整扫描重建索引，可以找出差异，并恢复C05的冲突标记；它需要再次检查50条记录、写入50条目。另一项实际快照变更检查，在校验失配后停止查索引，没有作出应用判断。

由此须区分文件完整、快照匹配和关联完整。摘要能帮助识别指定内容，不能证明关系是否归对、有没有把重要证据放到别处。关联索引应作为可审查、可修订的成果保存，而不能被当作无须核验的权威。

## 能向书中交付什么

本轮的条件推论是：结论写清范围能阻止部分误用；充分资料使检查成为可能；可靠关联可以把一次整理分摊到多次使用，减少指定策略下的重复检索。能否改善现实复用净收益，仍取决于使用频率、变化、维护成本、实际阅读方式及索引错误。

下一步适合选少量本仓库真实论证卡与来源记录，人工核查关联是否完整、范围是否足够清楚，再考虑有参与者的时间对照。当前未做这一步，不借本轮结果证明社会组织的普遍学习定律或Open Business唯一必要。
