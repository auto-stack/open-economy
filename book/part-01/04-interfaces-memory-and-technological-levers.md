# 接口、记忆与技术杠杆

半年后，想象一下，接班人第一次翻开泵房的交班本。他看见了密封圈的规格，还看见前一位维修者写下的一行字：“水压低时，改用新规则。”字迹清楚。他抬头看一眼表，又低头看一眼本子。多低才算低？说的是墙上这只新表，还是墙角那只已经拆下来的旧表？

写字的人当时都知道，用不着提醒自己。他有一间熟悉的泵房作注脚。半年后，字还在原处，那个能随口解释它的人已经交班了。要让一种本领跟着记录走，我们要留给下一班人什么？

## 能插进去，就能接班吗

一台备用电机到了，插头居然正合适，挺让人高兴。等一等。电压对吗？带得动原来的泵吗？维修者用不着把电机拆开研究每一匝线圈，却得知道尺寸、转速、启动条件，以及出了异常它会怎样。这些条件交代清楚，更换内部零件才有可能只惊动修电机的人。

软件设计者Parnas遇到的是同一类麻烦。一段程序里有个日后很可能改变的决定，该让多少别的程序知道？他的建议是，把这个决定交给一个模块管，外面只依赖说好的用法。内部换了做法，只要承诺的行为仍能做到，调用它的地方便可以少改几处。即使代码完全公开，这种“信息隐藏”依然有用。省下的返工还得与调用和实现的开销一起算。[^interfaces]

到了细胞里，边界更有意思。Hartwell等人讨论的功能模块，有些靠空间隔离，有些待在同一处，却只和特定对象发生作用。同一个组分还可能兼好几份差事。想给每份功能裁一个互不重叠的小盒子，这些兼职者就会让画图的人犯难。这里说的是生物学家提出的一种研究框架。[^biology]

回到电机，我们给那份可依赖的约定一个名字，叫**接口**。装在什么地方，吃进什么，交出什么，碰到什么情形需要停下来，这些都可以是约定的一部分。图上用一刀把两边分开很容易。要知道这一刀切得好不好，得看一边动了以后，另一边还要跟着改多少。

动手做过一半的活，最好存下来？想象装配台随时可能被借走。只要中断时损失的是手上还没装完的那段，已经收好的几段日后都能接对，分段保存就可以省返工。但给每段装盒、写标签、重新检查也费工。只有省下来的比这些工夫更多，分段才划算。这正是本书分段模型的条件。[^module-model]

维修手册的难处也在这个分寸上。接班人不必从头学会绕线圈，可若省掉电压单位，省下的是写字的工夫，添上的是下一班的风险。留下解释时，读数的单位、误差、试过的期限和失败条件，都可能是别人下一步要倚靠的东西。

## 一本字字无误的旧手册

把交班本锁进防潮柜，半年后取出来，一个字都没糊。可这期间换过传感器，表盘的刻度也改了。接班人现在要查两件事。当年究竟记了什么？当年的话放到这只表上还管用吗？

本书在宽泛的意义上说**记忆**，只要过去留下的变化还能通过某条路径影响后来，就值得追究。手在练习中学会怎样用力，是一条路径。人翻开旧手册，找到上次异常的读数，是另一条。一本无人找得到的手册，内容可以保存得很好，通向眼前行动的路却断了。至于一个人怎样记得自己的经历，后面还要专门去看。

不妨造一块虚构的指示牌。阀门只有开、关两种状态，每期都有0.1的概率翻转，处在平稳分布时开、关机会各半。交班人在牌上如实写下当时的状态，随后封笔。过一期，按牌子猜还有0.9的机会猜对。过五期，阀门可能来回翻过，猜对的概率降到了约0.664。重复这个游戏，牌面上“开”“关”两种记录的分布始终各半，熵仍是1 bit。眼前这块牌子上的油墨也丝毫没褪。给出不同的翻转规律，或者允许后来者换一种办法解读旧牌子，就要另算。[^memory-model]

交班室里存了一百本这样的手册，说明柜子很能装。要知道它们今天能帮多少忙，得翻开一本，对一对眼前这台泵究竟换过什么。

## 一道每次都算出六的算术题

现在请你替一份虚构的报告做一次复核。纸上有三个读数，2、4、6。平均多少？你心算得4，报告上却写着6。好在文件齐全。你按下“重算”，结果还是6。再来一次？电脑耐性比人好，这一回它仍然答6。

打开计算步骤，谜底很小。三个数加起来是12，程序除以了n−1，也就是2，算术均值该除以n，也就是3。这个程序忠实地重复了同一个错误。改好以后也值得同时保留旧版本和改动理由。如果只把纸上的6描成4，已经拿那个6作过决定的人，往后连自己该回头查哪一笔都不知道。文件校验能认出大家手里是不是同一份程序，至于除数对不对，还得有人懂这道题。[^record-example]

Sandve等人给计算研究者的建议因此颇为实在。留下确切版本、输入、参数和中间结果，让读者能从文中的一句话找回产生那个数的过程。这些做法让别人有路可查，实际省下多少工夫，还得看任务。[^workflow]

现实中的复算有时真得找原作者搭把手。Hardwicke等人从一家期刊筛出35篇原则上已有可复用数据的文章，试着按既定判据复算其中一些结果。11篇可以自己做成，另有11篇在原作者帮助下做成，余下13篇仍有部分数值对不上。这35篇经过筛选，每篇也只查了一部分结果。要知道哪一处差异会改变论文结论，还得就那一处接着往下查。[^reproducibility]

下次听到“已经核过了”，可以多问半句，核到了哪一步？有时是文件终于找到了，有时是重算出了同一个数，有时连除数都检查过了。至于换到另一间泵房这项建议能不能用，只有把两间泵房的条件摆在一起才知道。

## 给半年后的读者留几句话

假如交班人只能再写几行，什么最值得写？哪只表出过错，依据是哪天的读数，有谁试过另一种解释，还有哪种工况从没试过。这几行会直接改变下一班敢不敢照着做。

资料管理也有相应的办法。FAIR原则让人能找到资料，知道怎样申请访问，用什么词汇和许可复用。W3C的来源模型则像给记录配一份来历，能记下谁做了什么、从哪一版改来，连这份来历是谁提供的也可以追查。文件即使有来历、拿得到，里面那道除法题仍值得亲手算一次。[^provenance]

本书整理证据时，用这样一张六项小卡给接手者留话。

| 项目 | 留给后续使用者的问题 |
|---|---|
| 主张与地位 | 说的是什么，是文献结果、条件推论、假说还是价值主张？ |
| 来源及作用 | 谁在哪一版、哪个位置说了什么，它支持或限制哪一层意思？ |
| 反向材料 | 存在什么更正、质疑、替代解释或条件外情况，回应到哪里？ |
| 适用边界 | 对什么对象、任务、时间、单位和条件成立？ |
| 已查与未知 | 实际检查了什么，还有什么没有读、没有算或没有验证？ |
| 当前用法与复核 | 现在怎样使用，什么新情况会触发重新检查，由谁继续维护？ |

尤其值得好好填的是“反向材料”那一栏。一位作者更正了数据，一位同行提出另一种解释，或一项假说至今还在等直接试验，留给下一位读者的工作大不相同。三篇文章沿用同一份数据时，三条引文也只能把人领回同一批观察。

这件事在一份跨文化博弈论文的校样里就出过考题。同一份文件收着目标论文、Binmore的评论和作者的答复。读到一段关于金钱自利的反驳，得先看这会儿轮到谁说话。质疑实验参与者怎样理解题目，与指出哪笔数据有误，是两种不同的意见。[^disputes]

一项关于足球与共同认同的研究又有另一层麻烦。读者可以在同一个期刊页面上，先读到原摘要，再点进更正。作者承认了哪些数据问题？复核者质疑的是个人认同的变化，还是国家之间冲突的解释？答复处理了哪一层？顺序读完，仍有争议就把争议留下。拿旧摘要里的幅度当现成参数，会把真正需要讨论的地方遮住。[^disputes]

## 索引也会指错路

索引最令人感激的时候，是你记得有过一份更正，却完全想不起放在哪儿。它最容易误导人的时候，也恰好如此。一个链接能把你领到一篇论文。论文究竟做过这项试验，还是只提议将来做一做，还得翻到相应的段落。

我们用七个编出来的情境试了三种存法。只留结论和明写的范围，能挡住两次明显越界的使用，另外五次都缺判断依据。留下全套资料，按给定检查规则逐份找，可以答完七题。再多做一份关系正确的索引，也答完七题，找的时候却可以直接翻到对应记录。拿全套资料自己先编一遍同样的索引，效果便相同。[^comparison]

省下来的究竟是什么？上一个人找过的关系，下一个人可以顺着走。编索引、读入和核对相应版本的材料，都有开销。我们还预先在材料里写明了每条记录归谁。从真正含混的文章里辨认谁支持什么，要花多少人工，这笔小试验没有量。

再故意把一条反对意见挂到隔壁主张名下。原件一份没丢，索引上的编号也一个不少，照着索引的人偏偏漏看了它。把全套材料重新梳理一遍，可以在这个例子里找回这条异议，代价是有人得重新做这份活。

翻回本书自己用过的几张论证卡，我们也找到了埋得太深的更正和适用条件。另外一些主张就算给足链接，也还在等直接试验。有些麻烦可以靠整理解决，有些得去取得新证据。这次小范围回查没有给读者计时，也没测量实际放错链接的频率。[^card-audit]

## 改成四以后，告诉谁

回到那道均值题。你改好了程序，昨天收到6的人却还照旧数安排工作。一个允许修订的共同记录，得给他们留下机会，看清自己当时用的是什么、现在变了什么。

还有一种改动发生在研究者自己脑子里。一开始就写下的预测，与看完数据后才想通的解释，都值得留下。预先记录分析计划的研究建议把这两种经历分清楚，改变主意时记下当时已经看到了什么。靠这份记录可以追问新解释下一次能预测什么。至于有没有挑结果来讲，仍要核查。[^revision]

本书试用的办法，是先请质疑者指到具体的一句话和一个版本。双方先核对是抄错数、做错步骤，还是条件变了、解释有分歧。把理由、当时看过的材料和必要的检验随更正留下来，再沿已知的使用关系，告诉那些可能需要重算的人。收到通知只表示该查一查。没写进文献、只在走廊里口头传过的那个6，索引也未必找得到。

能指出除数有误的人，未必有权替所有人宣布新版生效。提出质疑、审核、发布，以及现场决定从哪天换用新版，可以由不同的人负责。几个解释仍有分歧时，共同工作也可以继续，只要大家知道眼下用哪一版，过渡期间出问题找谁。

换作出门旅行的约定，这个区别立刻就熟悉了。你能改共享日历里的出发时间，可同伴也许已经按旧时间买了车票。谁有权改，怎样让受影响的人知情、拒绝或退出，谁承担退票损失，都是需要说出理由的制度和价值问题。

## 一个好工具，要用到第几期才划算

交班本写得好，下次查漏也许能省两小时。新电机装得好，同样一班人也许能多送些水。工具、知识或做事办法改变了同样投入所能完成的任务，这就是本书所说的**技术杠杆**要研究的事。

把旧办法和新办法放在同一张工单上，先约好质量、期限和能用的资源。新接口让哪一步免于重做，记录省了谁的查找，还是新工具反而多了一道每周必做的检查？知道哪一笔变了，才知道怎样比较。

拿本书的一个算例来说，每期有10单位投入，先留4给日常维护。旧工具做一件成果花2，余下的6够做3件。新工具每件只花1，光看这一条，很难不心动。再看说明书，还要一次花8安装，以后每期另花2养护。假定安装可跨期安排，产出的东西同质可加，用T期，旧法合计3T，新法是4T−8。第八期收工，两边恰好都是24件。只有装得起、也用得到第九期及以后，新工具才开始领先。[^lever-model]

这本账还空着几栏。谁愿意先垫安装费，做出的东西有没有人要，省下的工夫归谁？多一件可选工具，和要求所有人从明天起一律换新，是两种处境，后者可能让只需短用的人吃亏。

信息工具同样有这笔账。一份更正可以一夜送到更多人手上，一道除错了的算式也可以。收到一百份相同的6，仍然只用过那一道除法。核验、适配、通知和维护的工夫都要算进去，才知道更快的传播带来了什么。

## 哪些好处还要看下一次交班

有三件事，我们愿意留作待验证的假说。

1. 若同类任务常出现，留下证据、边界和核查经过，可能让后来者少花工夫。使用次数很少、条件换得很快，记录本身反而可能更费力。
2. 说清接口再允许局部替换，可能让一次改动少牵扯几个人。若没写出关键依赖，或每次换件都得重谈接口，省下的返工也可能消失。
3. 留下异议、修订理由，再通知用过旧版的人，可能让共同纠错容易些。关系记对了没有、谁有权发起更正、谁肯花时间核查，都会左右结果。

要说这些做法提高了组织的Ordo，还得观察它们使哪件事更容易持续、协作、适应或发展，在哪个任务和尺度上付出了什么。一间泵房可以积攒满柜手册，仍然要等换班那一刻，才知道谁真能把故障排掉。

## 从保存和修订进入演进

维修记录能让下一班人查到规则为什么改过。等原来的维修者离开，现场还多了两件要确认的事。接任者能否独立处理这次故障？其他人遇到异常，知不知道现在该找谁？下一章从一组换过成员的电话装配者写起，追踪做法怎样越过一次交接，又在哪里失落。[下一章《组织怎样演进》](05-how-organizations-evolve.md)

再往后，[一个人](../part-02/01-human-as-organization.md)会记住练习时手上的感觉，[一群作过约定的人](../part-03/02-revisable-shared-commitments.md)会记住谁曾承诺什么。到了经济与Open Business，维护共同成果有了更切身的问题，报酬给了谁，半夜接电话的又是谁？要回答它，得先看看本领怎样传到下一双手里。
